## 二、架构模式

### 2.1 微信小程序原生架构

tpl-app-mini 采用**微信小程序原生架构**，不引入第三方框架：

- **页面 (Page/Component)**：使用 `Component()` 构造器（glass-easel 组件化模式）
- **数据绑定**：单向数据流，通过 `setData()` 触发视图更新
- **事件通信**：`triggerEvent`（子→父）、`wx.navigateTo` 参数传递（页→页）
- **全局状态**：`getApp().globalData` + `wx.getStorageSync/setStorageSync`

### 2.2 页面组件化

所有页面均使用 `Component()` 而非传统的 `Page()` 构造器，这是 glass-easel 组件框架的推荐模式：

```
Component({
  data: { ... },        // 页面数据
  methods: { ... },     // 事件处理
  lifetimes: {          // 生命周期
    attached() { ... }
  }
})
```

### 2.3 与 Web 前端的架构差异

| 维度 | tpl-app-web (Vue 3) | tpl-app-mini |
|------|-------------------|-------------|
| 路由 | Vue Router 声明式路由 | 小程序页面栈（`app.json` pages 配置） |
| 状态管理 | Pinia store | 全局数据 + 页面级 data |
| HTTP 客户端 | Axios (拦截器、封装) | `wx.request` |
| 组件通信 | props / emit / provide-inject | properties / triggerEvent |
| 生命周期 | Vue 生命周期钩子 | 小程序生命周期 (`attached`, `ready`, `detached`) |
| 样式作用域 | scoped CSS / CSS Modules | WXSS 样式隔离 |
| 跨页面数据 | Pinia / Vue Router params | `wx.setStorageSync` / 页面栈传参 |

## 三、数据流

### 3.1 用户交互数据流

```
用户操作 → Component.methods 事件处理
    │
    ├── 纯前端操作 → this.setData() → WXML 更新
    │
    └── 需后端数据 → wx.request()
                        │
                        ├── 成功 → 解析 response → this.setData()
                        │
                        └── 失败 → 错误提示
```

### 3.2 微信登录流程（当前实现）

```
app.onLaunch()
    │
    ├── wx.getStorageSync('logs') → 读取历史启动日志
    │
    └── wx.login()
            │
            └── 获取 code → console.log(code)
                    │
                    └── [待实现] 发送 code 到 tpl-app-api 换取 token
```

### 3.3 目标数据流（完整实现后）

```
┌──────────┐    wx.login()     ┌──────────┐   POST /auth/login   ┌──────────────┐
│ 微信客户端 │ ────────────────▶ │ tpl-app-  │ ──────────────────▶ │  tpl-app-api  │
│          │ ◀──────────────── │   mini   │ ◀────────────────── │ (Spring Boot)│
└──────────┘   access_token    └──────────┘    Sa-Token JWT      └──────────────┘
                                                         │
                                                         ▼
                                                  ┌──────────────┐
                                                  │  PostgreSQL  │
                                                  │  + Redis     │
                                                  └──────────────┘
```
